title: ContextMenu
description: A menu for what it wraps, at the pointer or from the keyboard.

Wrap a control in `ContextMenu` to give it a menu. The menu opens on the platform's secondary press (a right-click, or a Control-click on a Mac) at the pointer. From the keyboard, `Shift+F10` or the context menu key opens it beside the focused control. It uses the same items, and the same menu, as a [Dropdown](/docs/components/dropdown).

## With parameter controls

`parameterMenuItems(parameter)` builds a parameter's usual items:

- **Reset to default**: one host gesture and one undo step, as a double-click is. It is disabled when the parameter is already at its default.
- **Enter value…**: only with `onEnterValue`. It calls your function to open a field of your own, as the demo's `Modal` does.
- **Copy value** and **Paste value**: the parameter's own `format()` goes to the system clipboard, and pasted text is read back with its `parse()`. Text that isn't a value changes nothing.

```tsx
import { ContextMenu, Knob, parameterMenuItems } from '@soundor/components';
import { parameters } from 'soundor:parameters';

<ContextMenu items={() => parameterMenuItems(parameters.gain)}>
  <Knob parameter={parameters.gain} />
</ContextMenu>;
```

Give `items` a function, as here, and it runs each time the menu opens, so the items show the parameter's state at that moment. Spread the result into a list of your own to add items. A read-only parameter's items are disabled, except Copy.

A ContextMenu doesn't change the control it wraps. Knob, Slider, Fader, XYPad and Plot markers act on the primary button only, so a secondary press starts no drag and opens no gesture. A secondary press during a primary drag opens nothing. Keyboard focus, the control's own keys, double-click reset and parameter bindings work as before. The menu's actions start host gestures only when they change a value.

Parameter context menus aren't added to the controls automatically: wrap the ones that should have one.

## Layout

ContextMenu renders a view around its children, laid out as a column like any view. In a row it is as wide as its child; where the child should grow, give the wrapper `containerStyle={{ flex: 1 }}`.

## Keyboard and accessibility

| Input                                | Does                                                          |
| ------------------------------------ | ------------------------------------------------------------- |
| Secondary press                      | Open at the pointer, with focus on the menu                   |
| `Shift+F10`, or the context menu key | Open beside the focused control, with focus on the first item |
| `↑` / `↓`, `Home` / `End`, a letter  | Move between items                                            |
| `Enter`, `Space` or a click          | Run the item                                                  |
| `Esc`, `Tab` or a click outside      | Close, and give focus back to the control                     |

## Engine support

- **Secondary press:** Soundor's `contextmenu` event, on the secondary button going down in the VST3 and web runtimes, with its position in the view. The web runtime's own browser menu is kept away.
- **Clipboard:** `soundor:ui`'s `clipboard`. Copy and Paste are only offered where the runtime has one. A clipboard the platform refuses, such as a browser that denies permission to read it, makes them do nothing rather than fail.
- **Not available:** Soundor has no long-press-to-open on touch screens. Screen-reader users open the menu with `Shift+F10` or the context menu key: a custom accessibility action has to be listed by the focused control itself, and the existing controls don't take extra actions. The context menu key is reported where the platform reports it; `Shift+F10` works everywhere.
- A menu is drawn inside the editor, as every Soundor overlay is, and is held within the editor's bounds. It can't extend past the plugin window as a system menu can.
