---
title: Migrating to 0.4
description: Dropdown, ContextMenu and Plot became compositional.
---

0.4 replaces the configuration props of three components with parts you compose: `Dropdown` becomes `DropdownMenu`, `ContextMenu` takes a trigger and content, and `Plot` takes its axes, series and markers as children. The other components are unchanged. There is no compatibility layer: each old prop is gone, and TypeScript points at every place to change.

## Dropdown

`Dropdown` is now `DropdownMenu`. The `trigger` prop becomes a `DropdownMenu.Trigger` around the same element, and `items` become `Menu.Item`s and `Menu.Divider`s in a `DropdownMenu.Content`. `side`, `align`, `offset`, `anchor`, `size`, `accessibilityLabel`, `debugId`, `style` and `styles` move to the content; `open`, `defaultOpen` and `onOpenChange` stay on the root.

Before:

```tsx
<Dropdown
  align="end"
  trigger={<Button>Options</Button>}
  items={[
    { id: 'reset', label: 'Reset', onSelect: reset },
    { type: 'separator' },
    { id: 'snap', label: 'Snap to grid', checked: snap, onSelect: toggleSnap },
    { id: 'paste', label: 'Paste', disabled: !canPaste, onSelect: paste },
  ]}
/>
```

After:

```tsx
<DropdownMenu>
  <DropdownMenu.Trigger>
    <Button>Options</Button>
  </DropdownMenu.Trigger>
  <DropdownMenu.Content align="end">
    <Menu.Item onPress={reset}>Reset</Menu.Item>
    <Menu.Divider />
    <Menu.Item checked={snap} onPress={toggleSnap}>
      Snap to grid
    </Menu.Item>
    <Menu.Item disabled={!canPaste} onPress={paste}>
      Paste
    </Menu.Item>
  </DropdownMenu.Content>
</DropdownMenu>
```

| 0.3                                       | 0.4                                        |
| ----------------------------------------- | ------------------------------------------ |
| `{ id, label, onSelect }`                 | `<Menu.Item onPress>{label}</Menu.Item>`   |
| `disabled`, `icon`, `hint`, `checked`     | the same props on `Menu.Item`              |
| `{ type: 'separator' }`                   | `<Menu.Divider />`                         |
| `id`                                      | a `key`, where the items come from a `map` |
| `DropdownTriggerProps`                    | `DropdownMenuTriggerTarget`                |
| `MenuItem`, `MenuAction`, `MenuSeparator` | removed: write the items as elements       |

`onPress` runs when `onSelect` did: after the menu has closed and given focus back. `Menu.Label` is new, a heading over a group.

## ContextMenu

`ContextMenu`'s child goes in a `ContextMenu.Trigger`, and its `items` become a `ContextMenu.Content`. `size`, `accessibilityLabel`, `debugId`, `style` and `styles` move to the content; `disabled` and `onOpenChange` stay on the root. `parameterMenuItems(parameter, options)` is now the `ParameterMenuItems` component, with the same options as props.

Before:

```tsx
<ContextMenu
  items={() => [
    ...parameterMenuItems(parameters.gain, { onEnterValue }),
    { type: 'separator' },
    { id: 'learn', label: 'MIDI learn', onSelect: learn },
  ]}
>
  <Knob parameter={parameters.gain} />
</ContextMenu>
```

After:

```tsx
<ContextMenu>
  <ContextMenu.Trigger>
    <Knob parameter={parameters.gain} />
  </ContextMenu.Trigger>
  <ContextMenu.Content>
    <ParameterMenuItems
      parameter={parameters.gain}
      onEnterValue={onEnterValue}
    />
    <Menu.Divider />
    <Menu.Item onPress={learn}>MIDI learn</Menu.Item>
  </ContextMenu.Content>
</ContextMenu>
```

- **Items made at opening.** `items` as a function ran each time the menu opened. The content now renders as it opens, so the items read the state at that moment without one.
- **An empty menu.** A menu whose content renders no item still opens nothing, but `onOpenChange` now hears `true` and then `false`.
- **`longPressDelay` is gone.** A long touch opens the menu on the platform's long press, which Soundor's engine recognises ([soundor/soundor#399](https://github.com/soundor/soundor/pull/399)); the delay is no longer the component's to set. `longPressDelay={0}`, which turned it off, has no replacement: a control whose own touch gesture conflicts should stay out of a ContextMenu.
- The trigger keeps its child's role, name, value, actions and focus, as before, and the engine's `showContextMenu` action is offered after the child's own actions. It replaces the custom `showMenu` ("Show menu") action.

## Plot

The configuration props become parts. `x` and `y` are `Plot.XAxis` and `Plot.YAxis`; each entry of `series` is a series part named after its `type`; each entry of `markers` is a `Plot.Marker`, or a guide line for one with a single coordinate; `legend` and `readout` are `Plot.Legend` and `Plot.Readout`. The grid is `Plot.Grid`, and is drawn only where you add it.

Before:

```tsx
<Plot
  width={440}
  height={220}
  x={{ domain: [20, 20_000], scale: 'log', format: formatters.frequency }}
  y={{ domain: [-24, 24], format: formatters.decibels }}
  series={[
    { label: 'Input', type: 'area' },
    { label: 'EQ', type: 'line', points: response, extend: true },
  ]}
  seriesSource={spectrum}
  markers={[
    ...bands.map((band, i) => ({
      x: band.hz,
      y: band.db,
      label: String(i + 1),
      onMove: ([hz, db]) => moveBand(i, hz, db),
    })),
    { y: 0, dash: [3, 3] },
  ]}
  legend
  readout
/>
```

After:

```tsx
<Plot width={440} height={220}>
  <Plot.XAxis domain={[20, 20_000]} scale="log" format={formatters.frequency} />
  <Plot.YAxis domain={[-24, 24]} format={formatters.decibels} />
  <Plot.Grid />
  <Plot.Area label="Input" source={inputSpectrum} />
  <Plot.Line label="EQ" points={response} extend />
  {bands.map((band, i) => (
    <Plot.Marker
      key={i}
      x={band.hz}
      y={band.db}
      label={String(i + 1)}
      onMove={([hz, db]) => moveBand(i, hz, db)}
    />
  ))}
  <Plot.HorizontalLine value={0} dash={[3, 3]} />
  <Plot.Legend />
  <Plot.Readout />
</Plot>
```

| 0.3                                   | 0.4                                                        |
| ------------------------------------- | ---------------------------------------------------------- |
| `x`, `y`                              | `<Plot.XAxis …>`, `<Plot.YAxis …>`                         |
| the grid, always drawn                | `<Plot.Grid />`                                            |
| `type: 'line'` (or no type)           | `<Plot.Line>`                                              |
| `type: 'area'`, or `fill: true`       | `<Plot.Area>`                                              |
| `type: 'steps'`, `'bars'`, `'points'` | `<Plot.Steps>`, `<Plot.Bars>`, `<Plot.Points>`             |
| `type: 'band'`, `points` and `upper`  | `<Plot.Band lower upper>`                                  |
| `seriesSource`, by index              | `source` on each series                                    |
| a marker with `x` and `y`             | `<Plot.Marker x y>`                                        |
| a marker with only `y`, or only `x`   | `<Plot.HorizontalLine value>`, `<Plot.VerticalLine value>` |
| `legend`, `readout`                   | `<Plot.Legend />`, `<Plot.Readout />`                      |
| `overlay={(space) => …}`              | views inside the Plot, with `usePlotCoordinates()`         |
| `PlotSeries`, `PlotMarker` types      | each part's props: `PlotLineProps`, `PlotMarkerProps`…     |
| `PlotSeriesSource`                    | `PlotSource<PlotSamples>`, one per series                  |

- **Live data.** A `seriesSource` returned one snapshot for every series, by index. Give each series its own `source` instead, whose `get()` returns `{ points }` or `{ values }` (a band's, `{ lower, upper }`). One notification still draws one frame, with no React render.
- **Axes you leave out.** In 0.3, a plot without `x` or `y` drew a 0 to 1 axis. In 0.4, that axis spans the extent of the static data, or 0 to 1, and draws no line or labels.
- **Order.** Series are drawn in the order they are in the tree, as they were in the array; markers and guide lines over all of them. A default colour follows that order.
- **Overlay.** A component inside the Plot calls `usePlotCoordinates()` for the coordinates `overlay` was given. Its views render over the canvas where it is in the tree. `safeZone` stays on the Plot.

`@soundor/components/chart` keeps its drawing helpers. `PlotSeriesSource` is gone from it, `PlotMarker` there no longer has `onMove`, `onMoveStart` and `onMoveEnd` (the drawing helpers never used them), and `drawAxes` takes which axes to draw.
